## Why it is generated, not typed

The cost model lives in [`ai/aiops/policy.py`](../ai/aiops/policy.py) and is the
*same function* the policy engine uses to enforce the budget rule. So the number
in this document and the number that can reject a deployment cannot drift apart
— change a size in `platform.yaml` and both move together.

That is the whole reason the budget rule is arithmetic rather than a judgement:
"does this fit the budget" is a question a model should not be guessing at.

## What drives the cost

Reading the prod column, two things dominate and both are HA decisions:

- **Multi-AZ Postgres doubles the database line** — $105 becomes $210. This is
  the single largest item in production.
- **NAT gateways scale with AZ count** — $33 each, one per AZ for zone
  independence, so 3 AZs is $99. In dev a single shared NAT saves $66.

Compute is the *third* largest item in prod, which is the counter-intuitive
part: at this scale the availability guarantees cost more than the application.

## The dev/prod lever

`cost_optimized` in dev buys a 63% saving on an otherwise identical topology:

| | dev (cost-optimised) | prod (HA) |
|---|---|---|
| Nodes | spot, −35% | on-demand |
| NAT | 1 shared | 1 per AZ |
| Database | single-AZ | multi-AZ (×2) |
| Backups | 3 days | 14 days |
| **Monthly** | **$107** | **$515** |

The policy engine enforces that these are mutually exclusive: `high_availability`
and `cost_optimized` together is a violation, because spot capacity can be
reclaimed with two minutes' notice and that is not compatible with a 99.9% SLO.

## AI spend

Small, and deliberately structured to stay small:

| Operation | When it calls the model | Cost |
|---|---|---|
| `gate` on a clean release | never — decided by rules | **$0** |
| `gate` on a crash loop | never — decided by rules | **$0** |
| `gate` on ambiguous evidence | once | ~1–3¢ |
| `plan-env` | once per environment plan | ~2–4¢ |
| `plan-command` | once per PR command | ~1–2¢ |

The triage stage is a cost control as much as a safety one. Most deploys are
unambiguous, so most deploys are free. At ten deploys a day with one ambiguous
verdict a week, AI spend is well under **$5/month** — three orders of magnitude
below the infrastructure it is protecting.

## What this excludes

Stated plainly, because a cost estimate that hides its exclusions is worse than
no estimate:

- **Data egress.** Usually the largest surprise on a real bill and entirely
  traffic-dependent.
- **Backup storage beyond the included allowance**, and any snapshot retention
  past the configured window.
- **Cross-AZ traffic** between pods and the database.
- **Per-cloud unit price differences.** The estimate is cloud-neutral by
  construction: sizes are t-shirt sizes and each stack maps them to comparable
  machines (`m6i.large` ≈ `e2-standard-2`). Real invoices differ by a few
  percent, and sustained-use discounts on GCP typically make it cheaper for the
  same shape.
- **Support plans, observability vendors, CI minutes.**

It is sized to catch an order-of-magnitude mistake and answer the budget
question. It is not a billing system, and this document does not pretend it is.
